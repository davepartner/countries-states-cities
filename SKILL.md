# Countries · States · Cities — Dataset Builder

Give any app a **country / state / city dataset**, sliced to exactly what it needs and delivered in
the format its stack already uses. No API key, no third-party service, no database to install — one
Python tool reads the bundled data and emits the requested slice.

**Goal:** the smallest correct geography dataset for the job — nothing more, nothing less — so the
app loads fast and the user isn't dragging 170k cities when they only need US states.

> **Honesty rule:** this data is community-maintained and derived from the Countries States Cities
> Database (ODbL v1.0). Coordinates are centroid-level (not survey-precise), and `population` is only
> as fresh as its `population_year`. **Attribution is required** — keep `NOTICE.md` and
> `LICENSES/` with any copy of the data you ship. Verify critical facts (boundaries, disputed
> territories) against an official source before relying on them.

## The workflow

```
Clarify scope ─▶ Slice the data ─▶ Integrate ─▶ Verify
```

1. **Clarify scope** — decide, with the user, what they actually need (see *Scope* below). Ask one
   short question if it's ambiguous: *"Just the countries, or states too? Any specific region?"*
2. **Slice** — run `tools/subset.py` with the matching flags (`references/subsetting.md`).
3. **Integrate** — wire the output into the app (`references/integration.md`): SQL tables + seed,
   JSON served to the frontend, or CSV imported by the admin.
4. **Verify** — confirm the slice loads and the counts match expectations; keep attribution.

## Scope (what to include)

| The user wants… | `--scope` | `--country` / `--region` / `--state` |
|---|---|---|
| Only a list of countries | `countries` | `--region Africa` or `--country US,CA` |
| Countries + their states | `countries,states` | `--region Europe` |
| Cities in specific states | `countries,states,cities` | `--state US:CA,US:NY` |
| Cities in specific countries | `countries,states,cities` | `--country NG,GH` |
| Counties too (US counties, FR arrondissements…) | `countries,states,counties,cities` | `--country US` |
| Everything incl. postcodes | `all` | `--country DE` |

Countries are keyed by ISO2 (`US`), states by ISO 3166-2 (`CA`), cities/counties by Wikidata QID
(`Q62` = San Francisco). Foreign keys are natural (`country_code`, `state_code`, `county_code`,
`parent_code`) — no surrogate IDs. See `references/data-model.md` (or `SCHEMA.md`) for the field
reference.

## The tool

```bash
python3 tools/subset.py data OUT --scope ... [--region ...] [--country ...] [--state ...] \
    [--format json|csv|sql|xml|yml|geojson|mongodb|parquet] [--sql-dialect ...]
```

Every flag is optional and combinable. The output is always internally consistent (parents and
cross-referenced counties are pulled in automatically). Full reference + more examples:
`references/subsetting.md`.

```bash
# Just the countries, as JSON
python3 tools/subset.py data out --scope countries

# European countries and their states, as CSV
python3 tools/subset.py data out --scope countries,states --region Europe --format csv

# Cities in California + New York, as PostgreSQL SQL
python3 tools/subset.py data out --scope countries,states,cities --state US:CA,US:1 \
    --format sql --sql-dialect postgresql

# Everything for Nigeria
python3 tools/subset.py data out --scope all --country NG

# Whole world, every format (no filters)
python3 tools/export.py data out
```

## Integration

- **SQL backend** — `--format sql --sql-dialect <db>` produces `schema.sql` + `data.sql`; run them
  against MySQL/Postgres/SQLite/SQL Server, then read with your ORM.
- **JSON / frontend** — `--format json` gives `countries.json`, `states.json`, `cities.json`
  (keyed and FK-consistent); serve them statically or import into the frontend.
- **Dropdowns / pickers** — for a cascading country → state → city selector, take
  `--scope countries,states,cities` and link by `country_code` / `state_code`.
- **CSV / spreadsheet** — `--format csv` for admin import or user-facing exports.
- **GeoJSON** — `--format geojson` for maps (Point features).

Per-stack recipes and gotchas: `references/integration.md`.
